# TransCourse 개발가이드

## 기술 스택
- Java 21, Spring Boot 4.1.x
- Spring Data JPA, MySQL 8.4
- Spring for Apache Kafka, Kafka 4.0 (KRaft)
- MinIO (S3 호환), FFmpeg
- JUnit5, Mockito

## 패키지
```
com.example.transcourse
├── domain
│   ├── video
│   │   ├── controller    // 업로드, 상태 조회, 산출물 접근 API
│   │   ├── facade        // 스토리지와 서비스 조율
│   │   ├── service
│   │   ├── entity
│   │   ├── event         // 업로드 완료 도메인 이벤트
│   │   ├── dto
│   │   ├── repository
│   │   └── exception
│   └── job
│       ├── controller    // 수동 재시도 API
│       ├── listener      // 커밋 후 발행
│       ├── messaging     // Kafka 발행과 유형별 컨슈머
│       ├── service       // 상태 전이와 실행
│       ├── processor     // 유형별 처리 구현
│       ├── scheduler     // 복구 폴러
│       ├── entity
│       ├── repository
│       ├── exception
│       └── experiment    // 리밸런싱 실험용 관측 장치
└── global
    ├── apipayload        // 공통 응답과 코드
    ├── config
    ├── exception         // 공통 예외와 advice
    ├── storage           // S3 저장과 키 규칙
    └── entity
```

## 처리 유형 추가
- `JobType`에 유형 추가
- `JobProcessor` 구현체 추가. `supportedType()`으로 유형 연결
- 짧은 작업은 `ShortJobConsumer`에 리스너 추가, 장시간 작업은 `TranscodingJobConsumer` 방식
- 업로드 시 작업 생성과 발행은 `JobType` 전체 기준이라 별도 변경 없음

## 상태 전이 관례
- 상태 변경은 `ProcessingJob`의 도메인 메서드로만
- 성공과 실패 기록에는 시작 시 받은 시도 번호 전달
- 기록 거부 예외(`StaleJobAttemptException`, `InvalidJobTransitionException`)는 `JobWorker`에서 실행 결과로 변환
- 산출물 키는 `StorageKeyFactory`로 원본 키에서 파생

## API 관례
- 응답은 `CommonResponse`의 `code`, `message`, `result`
- 오류 코드는 `ErrorStatus`에 정의하고 `GeneralException`으로 전달
- 예외 응답 변환은 `ExceptionAdvice`

## 테스트 관례
- 메서드명은 한글, 주어를 포함한 자립적 문장
- `@DisplayName`, `@Nested` 미사용
- 도메인 규칙은 단위 테스트, 컨트롤러는 `@WebMvcTest`
- `contextLoads`는 MySQL, MinIO, Kafka, FFmpeg 필요

## 주석 관례
- 코드에서 파생되는 구현 설명 금지
- 다른 파일에 근거가 있는 비자명한 제약만 기록
